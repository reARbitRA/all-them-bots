# 76) Budget-Based Fun Recommender Bot (“What should we do tonight?”)

## Concept Overview
A bot that recommends activities based on **budget + time + vibe** (solo/couple/friends, indoor/outdoor, chill/energetic) and optionally your city.

## Problem It Solves
- Decision fatigue (“where do we go?”)
- People over-spend because they don’t compare options
- Planning takes longer than the activity itself

## Key Features (MVP)
**Phase 1 (Week 1–2)**
- Quick quiz: budget range, time window, vibe, group size
- 3–7 recommendations with buttons: “More like this”, “Save”, “Not interested”
- Save favorites list

**Phase 2 (Week 3–4)**
- Personalization from feedback (simple rules)
- Weekly “Weekend ideas” digest
- “Plan card” message you can forward to friends

**Phase 3 (Week 5–8)**
- Mini App browsing (filters + map)
- Sponsored placements for venues

## Technical Architecture
- **Recommendation Engine**: rule-based scoring
- **Content Store**: curated activities (can start as JSON/CSV)
- **Scheduler**: weekly digest jobs
- Optional: **Venue map** via `sendVenue` / Google Maps link

## Database (minimal)
- `activities(id, city, title, cost_min, cost_max, tags[], location_json)`
- `user_prefs(user_id, city, budget_band, tags_like[], tags_dislike[])`
- `saves(user_id, activity_id, created_at)`
- `feedback(user_id, activity_id, action)` (like/dislike)

## Development Steps
- **Week 1**: FSM quiz + activity card UI (inline keyboard)
- **Week 2**: scoring function + “saved” view
- **Week 3**: weekly digest + basic personalization
- **Week 4**: admin import tool (`/admin_import_csv`)

## Monetization
- Premium: “unlimited cities”, “smart weekend planner”, “date-night pack”
- B2B: paid featured placement from venues (sponsorship)

## Pitfalls
- Don’t overbuild AI; curated + rules ships faster and works well early.
- Avoid scraping event sites in MVP (ToS risk). Use curated lists first.

# 77) Group Trip Coordinator Bot (tasks + itinerary + consensus)

## Concept Overview
A bot added to a **group chat** to coordinate: **who does what**, itinerary blocks, votes, reminders.

## Problem It Solves
- Group trips fail due to missing ownership
- Endless debates in chat without decisions
- Important info gets buried

## MVP Features
**Phase 1 (Week 1–2)**
- Create trip in group: destination + dates
- Add tasks with assignee: “Book hotel”, “Rent car”
- Simple itinerary blocks (Day 1/2/3)

**Phase 2 (Week 3–4)**
- Poll-based decisions: “Hotel A vs B”
- Reminders for task deadlines
- Pin-like summary message (bot reposts “Trip Summary”)

**Phase 3 (Week 5–8)**
- Expense splitting (optional)
- Mini App itinerary board

## Architecture
- Group-aware command handling
- Scheduler for deadlines
- Poll integration (`sendPoll`) or inline vote buttons

## DB Schema
- `trips(id, chat_id, title, start_at, end_at)`
- `trip_members(trip_id, user_id, role)`
- `trip_tasks(id, trip_id, title, assignee_id, due_at, status)`
- `itinerary_blocks(id, trip_id, day, time_block, title, notes)`
- `votes(id, trip_id, question, options_json, result_json)`

## Dev Steps
- **Week 1**: group setup + trip entity + permissions
- **Week 2**: tasks + reminders
- **Week 3**: voting + summary post regeneration
- **Week 4**: exports (PDF/text)

## Monetization
- Premium per trip (Stars) for advanced features (expense split, exports) 
- Or subscription for frequent travelers

## Pitfalls
- Group privacy: don’t DM people unless they’ve started the bot in private at least once (best practice).
- Always store `chat_id` and enforce roles for admin actions.
